# Как предложить расширение

[English](CONTRIBUTING.md) · **Русский**

## Как добавить расширение

1. Расширение лежит в **вашем публичном репо на GitHub** с лицензией. Все исходники должны быть в репо, а не
   только в релизе. Начать проще с [extension-template](https://github.com/KubekPanel/extension-template).
2. Опубликуйте **GitHub release** (не pre-release) с одним ассетом `.kubekext`. Тег совпадает с версией в
   манифесте: `1.2.0` или `v1.2.0` для `"version": "1.2.0"`.
3. Откройте PR, в котором:
   - файл `community/<id>.json`:
     ```json
     {
       "id": "com.yourname.discord-alerts",
       "repo": "yourname/kubek-discord-alerts"
     }
     ```
     Если `.kubekext` в релизе несколько, добавьте `"asset": "discord-alerts.kubekext"`.
   - строка в списке **Community** в `README.md` и **От сообщества** в `README.ru.md`, по алфавиту.
     Описание можно оставить на английском в обоих:
     ```md
     - [Discord alerts](https://github.com/yourname/kubek-discord-alerts) - Server crashes and joins in a Discord channel
     ```
4. CI скачает последний релиз и проверит его, код проверяется вручную.

Проверить заранее: `bun install && bun run validate --remote community/<id>.json`.

**Обновления** без PR: просто выпустите новый релиз, тег должен совпадать с версией в манифесте. Индекс
подхватит его в течение 6 часов. Если релиз не прошёл проверки, остаётся предыдущая версия, а предупреждение
видно в workflow Publish index.

## Правила

- `id` в reverse-domain и в нижнем регистре (`com.yourname.name`), одинаковый в манифесте и в имени файла.
  Префикс `com.kubek.` только для официальных.
- В манифесте есть `manifestVersion: 1`, `version` в semver, `name`, `description`, `author.name` и
  `engines.kubek`. Если иконка файлом, то это `.png` внутри пакета.
- Просите только те права, которые используете. В README объяснено, зачем каждое, особенно
  `servers:control`, `http:routes` и `http:outbound`.
- Код читаемый: без обфускации, backend не только в минифицированном виде, исходники frontend лежат в
  пакете.
- Данные уходят из панели только туда, куда их настроил пользователь (вебхук, API-ключ). Никакой
  телеметрии и отправки пользователей, логов или настроек куда-то ещё.
- Токены и пароли хранятся в полях `settingsSchema` с `"secret": true`.
- Не бандлите React и SDK, их даёт панель.
- В README описано, что делает расширение, что добавляет в панель и какие у него ограничения.

Записи, которые нарушают правила, долго не работают или потеряли репо, удаляются. Вредные ещё попадают в
`blocklist.json` с причиной, чтобы панели, где они уже стоят, предупредили пользователей. Нашли проблему?
[Откройте issue](../../issues/new/choose).

## Официальные расширения

В `official/<name>/` лежат исходники и собранный `.kubekext`. При каждом изменении поднимайте `version` и
пересобирайте `.kubekext`, `bun run validate` упадёт, если версии пакета и исходников расходятся.
